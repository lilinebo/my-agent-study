# 架构评审方法

## 用途

检查系统设计能否满足明确的业务与工程约束。

## 工作步骤

1. 明确业务场景、系统边界、规模、延迟、成本和运行环境。
2. 绘制模块职责、数据流、控制流和依赖关系。
3. 检查失败恢复、数据一致性、权限、可观测性、发布与回滚。
4. 对 AI 系统补充模型评估、工具权限、记忆边界及人工介入机制。
5. 比较方案取舍，优先提出可验证的最小改进。

## 输出模板

- 场景与约束：待填写
- 当前架构与依据：待填写
- 风险 / 触发条件 / 影响：待填写
- 方案比较与建议：待填写
- 验证方式与待确认项：待填写

不虚构规模与需求；企业经验必须脱敏。
