# 代码评审方法

## 用途

评审个人代码或明确授权的变更，发现会影响行为的具体问题。

## 工作步骤

1. 明确变更目的、范围和预期行为，阅读差异及必要上下文。
2. 检查正确性、边界条件、异常处理、权限、数据流和兼容性。
3. 对问题提供文件位置、触发条件、实际影响与修复建议。
4. 用已有测试或最小复现验证关键问题，注明未验证部分。
5. 按影响排序，区分必须修复的问题与可选建议。

## 输出模板

- 变更目标：待填写
- 问题 / 位置 / 触发条件 / 影响：待填写
- 建议与验证：待填写
- 残余风险：待填写

默认只读；不为风格偏好制造问题，不将公司代码复制到个人仓库。
