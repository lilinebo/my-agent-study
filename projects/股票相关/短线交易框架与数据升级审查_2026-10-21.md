# 林哥：短线交易框架与数据升级审查

日期：2026-10-21。本文是方法审查和待验证规则，不是当日荐股或经过验证的盈利策略。未修改插件、未安装服务、未下单。

## 已确认背景

- 可支配资金5,000元，最后确认空仓；未经用户更新，不推算余额与成交。
- 风格中等偏激进，最多持有5个交易日，买入日算第1天。
- 每天能看几次盘，不能持续盯盘。
- 最低佣金每笔5元；深市交易权限已知，创业板权限仍待核对。
- sources/与原始附件只作参考，不改动。

## 审查后的主要调整

1. 从“播报行情、等企稳”转为“市场条件—候选—触发—成交上限—失效—退出—记录”。
2. 一周内交易优先看板块和个股相对强度、量价结构、近端催化。半年报、股息和产业长期逻辑用于理解和排雷，不能直接证明5日内机会。
3. 抗跌是筛选线索，不是主动买点；当日上涨也不等于趋势反转。
4. 日内高点不是天然硬压力。初次突破可以参与评估，不能一概因“接近高点”否决；目标需来自有依据的价格结构，不能为了满足赔率倒推目标。
5. 均线是辅助。明确历史复权口径、已完成日线和当日未完成日线，不把均线精确到分当成确定支撑。
6. 不用一天涨跌频繁删除、重新推荐同一股票；保留当时的判断依据和升级/降级条件。
7. 此前聊天没有连续的实际成交记录，不能声称已验证胜率、盈利能力或避免了某笔实际亏损。

## 适合目前看盘时间的两种模式

### 模式A：强势股首次回踩后再转强

- 板块有同步支持，个股近期主动走强，而非仅跌幅较小。
- 先确认突破或上涨结构，回踩预先划定区域时成交收缩、价格没有持续失守。
- 在可看盘时，用新报价与已完成5/15分钟线核实再次转强，再考虑限价买入。
- 不提前挂单盲接下跌，不在错过计划后持续抬高成交价。

### 模式B：日线平台初次突破后的确认

- 盘前或前一晚画好平台，不事后移动标准。
- 主要评估已完成日线突破后的次日承接，或下午可看盘时仍有效的突破。
- 需板块支持、同时间成交比较与完整短周期K线。
- 若必须持续盯盘、几秒内决策才能管理，该机会不适合用户当前条件。

两种模式分别记录，不在失败后改成抄底、做T或长线。打板、连板接力与高频做T不作为初始主策略。

## 选股与名单管理

- 全市场可以用于判断板块；可交易候选先限制在账户已确认权限内。
- 周研究池约8～12只，按周复查，尽量减少同一板块重复；重大风险公告或结构破坏可即时降级。
- 当日计划池最多2只；“值得研究”“等待触发”“条件已满足”“计划失效”分别标注。
- 持仓观察优先于新股挖掘。候选数量不是强制推荐数量。
- 同时比较1/3/5日相对强度、板块内广度和量能，避免只按单日涨幅排名。
- 排查未来5个交易日的财报、减持、解禁、除权、停复牌、问询、异常波动等风险。
- 不用“主力净流入”推定真实机构意图；不同供应商资金流算法不混为一谈。

## 仓位、成本与风险

以下数值为初始管理参数，需用真实成交复盘优化，不代表已验证最优值。

- 初期通常同时只持1只；最多2只不同风险来源股票，合计仓位暂不超过60%。同题材两只不能当作分散。
- 常规初仓约1,500～2,000元。单只最多2,500元必须同时通过风险与交易单位校验；金额不是最低成交要求。
- 单笔计划风险先控制在40～60元（账户0.8%～1.2%），包括按结构失效价退出的价差、费用及合理滑点。
- 先确定合理失效位置，再按100股整数倍倒推数量；若100股也超预算，放弃，不人为缩窄止损。
- 扣费、考虑滑点后的潜在收益/计划风险原则上至少2，作为初筛而非胜率保证。
- 不为了摊低成本补亏损仓；没有新计划不加仓。
- 小账户优先一次买、一次卖。100股无法再卖一半，过多分批会增加最低佣金。

示例（虚构价格）：10元买200股，结构失效价9.80元，价差风险40元；假设往返费用约11元，计划风险约51元。若有依据的目标为10.60元，扣费潜在收益约109元，比例约2.1。若合理止损应在9.70元，原数量便不符合60元风险预算；需减量或放弃。实际费用和滑点需重新计算。

T+1、跳空、停牌、跌停或订单未成交可能令实际损失超过计划风险。风险预算不是损失上限保证。

若滚动5个交易日累计实际净亏损约150元，暂停新开仓并检查执行和市场；此为初始复盘阈值，不要求把亏损凑满才停。

## 买前必须写明的退出规则

1. 价格退出：在可卖时，结构失效则按预定条件处理，不临时扩大止损。跳空越过失效价时按可成交价格重新评估，不执着等原价。
2. 时间退出：买入后的两个交易日仍无有效进展，且突破不能保持或板块转弱，则退出，不无限延期。
3. 最长持有：买入日算第1个交易日，最迟第5个交易日计划退出；不得因亏损自动改为长线。停牌、跌停等无法成交时记录执行受限，最早可卖时处理。
4. 盈利退出：到预定目标、上冲失败或盈利结构破坏时退出。浮盈扩大后随确认的结构抬高防守，不机械按一分钱回撤退出。
5. 100股一般采用整体退出；更大数量只有扣费后有意义才分批。
6. 有条件单/提醒时，先验证券商是否支持、有效期和触发逻辑；触发不等于保证成交。

## 每次计划的输出格式

| 字段 | 要求 |
|---|---|
| 生成时间与有效期 | 北京时间；当日有效，价格结构或公告变化则重新计算 |
| 模式与催化 | 属于哪种模式，消息首次公开时间与原始链接 |
| 市场与板块条件 | 可比较时刻的广度、强度、量能 |
| 入场条件 | 可观察的触发，不只说“站稳”“企稳” |
| 买入上限 | 超过便放弃，不临时追价 |
| 股数及仓位 | 整手与可用资金校验 |
| 失效位置 | 来源、条件、可卖数量与T+1约束 |
| 目标和净赔率 | 目标证据，含费用与滑点 |
| 时间退出 | 最迟退出日期，节假日按交易日历计算 |
| 数据质量 | 完整、延迟、时钟偏差、缺项、来源 |

对于用户每天几次看盘的情况，优先安排上午开盘波动后与下午接近收盘前的复查；若只能看到旧快照，计划不能被描述为实时买入指令。本聊天本身不持续监控或自动下单。

## 已核实的插件问题

现有文件：A股行情分析助手0.1.5的scripts/quotes.py。

- query_time在网络返回后的normalize中取得，并非请求开始时间。
- 脚本只拒绝领先本机超过60秒的行情；其余负age也可能标实时。应输出clock_skew并降级，不计严格实时成功。
- 请求了开高低、昨收、成交量，却在标准化输出中丢弃，无法用该脚本完整支持量价分析。
- 没有标准日K或分钟线接口；前面聊天的临时补查不能当作插件稳定能力。
- 只按时刻判断交易阶段，缺真实交易日历和个股停复牌状态。
- 过期但字段合格的批量数据不会自动单股刷新；需区分“字段成功”和“符合实时请求”。
- 价格显式fltt=2、成交额按元输出，未发现已证实的缩放错误。
- 现有去重、有限重试、缺项回退和明确标识直接HTTPS的做法应保留。

## 数据升级顺序

### P0：产生可执行短线计划前必需

1. 稳定日K：120～250个交易日，开高低收、量额、前收盘、复权因子和公司行动；区分未完成日线。
2. 1/5/15分钟OHLCV与分时均价，至少覆盖近5～20个交易日；区分已完成分钟柱，不混用股/手。
3. 快照完整字段：开高低、前收、涨跌、累计量额、换手、成交时间、交易状态、涨跌停价；下单复核需最新报价。
4. 市场广度与板块：同一时点的涨跌家数、涨跌停、板块量价、成分与核心股；昨日/近5日同一时刻成交额。
5. 公告事件：原始公告与发布时间、首次披露/更新区别；未来5个交易日财报、解禁减持、除权、停复牌等。
6. 时间与来源：request_sent_at、response_received_at、source_time、上游名称、延迟、时钟偏差、错误与重试；两条数据线是否同一上游要明确。
7. 交易日历、证券主数据、交易单位与账户权限校验。

### P1：复盘与可靠性

- 缓存日K和分钟线、每日同刻快照、计划及实际成交，允许复算；字段成功/延迟/历史/收盘/时钟异常分类计数。
- 备源交叉核对，报价或历史价格冲突时停止精确下单计划。
- 只用当时已知的公告、成分与行情做回测；加入佣金、滑点、T+1、涨跌停、停牌、退市与公司行动。
- 分模式统计净收益、最大回撤、平均盈亏、最大浮亏/浮盈与交易执行偏差。先20笔检查纪律；更多样本和不同市场阶段再评估优势。

### P2：后续再考虑

Level-2、逐笔成交、龙虎榜、复杂资金流和更多技术指标。不得用这些替代P0。

## 插件与供应商建议

1. 优先升级现有插件到“快照+日K+分钟+板块/广度+公告”，不是再装多个只返回股价的工具。
2. 本次插件目录中未检出匹配的A股/Tushare/AkShare专用可安装结果；搜索并不穷尽目录。
3. Tushare有官方MCP接入文档，但本会话未连接，也不意味着有现成可点装插件。账户权限与实际工具暴露必须另行验证。
4. Tushare普通积分、实时日线、实时分钟、历史分钟为不同权限。官方本次价表：普通2000积分档200元/年，实时日线200元/月，实时分钟1000元/月。价格和许可在购买页再核实。对5000元账户，不建议为交易默认承担1000元/月实时分钟费用。
5. AkShare是接口库；其东财接口与现有东财链路同源，不能冒充独立备源。
6. 若已有同花顺iFinD等商业数据账号，先确认API、分钟/实时权限与使用许可，再考虑接入；普通同花顺App不等于拥有API权限。
7. 若低成本链路暂时无法稳定提供分钟线，采用已完成日线的次日确认策略，盘中用券商/同花顺核对；不冒充已实现自动分钟监控。
