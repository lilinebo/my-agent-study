## 2. 目标与明确不做的事情

把现有“查一个价格、解释涨跌”的工具，升级为：

**可信行情 → 市场/板块筛选 → 两类短线模式 → 可检验交易计划 → 人工确认券商执行 → 成交与退出复盘。**

第一轮不做打板、连板接力、秒级盘口博弈、高频做T、融资交易、创业板交易，也不扩展长期价值投资或为维持推荐数量强行选股。能判断一个候选不满足条件，比生成更多候选重要。

这是待验证的交易工作流，不是收益承诺。风险预算、赔率阈值和时间退出均需通过实际执行与样本检验。

## 4. 最小可行架构

采用一个小型Python数据核心，兼容现有脚本入口；如果实际已有服务器，就复用其结构，不平行重建一套服务。

```text
现有插件/脚本入口，或已验证的MCP入口
  └─ 数据服务与质量校验
      ├─ 东方财富公开接口适配器（现有）

      ├─ 交易所/巨潮公告及事件索引

      └─ 本地缓存、快照历史、错误记录
  └─ 账户权限与交易计划校验
      ├─ 候选筛选和模式识别
      ├─ 数量、费用、净赔率及T+1校验
      ├─ 提醒与条件单参数草案
      └─ 计划版本、实际成交与复盘
```

初期用SQLite或简单结构化文件保存数据即可，不上复杂数据库、消息队列、向量库或多服务部署。账户配置、成交与日志留在用户控制的位置；日志不写令牌、券商密码等凭据。

## 5. 分阶段实施与交付

以下为建议里程碑，不代表已有版本或固定交付日期。每阶段通过验收后再进入下一阶段。

### 阶段一：修复数据可信度——优先实施

**交付：可核验的快照、稳定历史日K、账户权限过滤、错误与缓存处理。**

- 快照输出开盘、最高、最低、最新、昨收、涨跌额/幅、成交量与单位、成交额、来源时间及状态；拿不到的字段为缺失，不填0。
- 记录请求发出、响应收到、标准化时刻和来源时间，区分请求耗时、行情年龄、主机/来源时钟偏差。
- 负行情年龄标记clock_skew，不计严格实时；保留可用报价但禁止凭异常时间生成实时入场结论。经独立时钟核对后才能解释偏差，不能悄悄把负值改0。
- 实时状态同时核对交易日、当前交易阶段与个股状态；午休、停牌、集合竞价、收盘阶段分别标注。
- 日K目标覆盖250个交易日，至少120个有效交易日；不足则声明可支持的指标范围。已完成日线与当日未完成日线分离。
- 保留未复权成交价格、复权因子与所用复权口径；历史形态用统一口径，实际下单使用真实未复权价格，不能直接复制调整后的价位。
- 缓存历史日K，增量更新；失败时可返回缓存供历史研究，但必须显示缓存日期，禁止冒充当日新数据。
- 已成功且新鲜数据不重复请求；批量遗漏、字段错误、过期记录分别处理。只对可恢复错误有限重试。
- 根据证券主数据建立深市主板A股可买范围。创业板（含300/301等）、其他市场/品种均不进入买入计划。代码前缀仅作初筛，最终以交易所和板块元数据为准；数据不明则不放行。
- 沪深及创业板指数可以用于市场判断，必须与“可买标的”严格区分；不能因为能查询创业板就推荐用户买入。
- 增加ST/退市风险、停牌、上市初期无涨跌幅限制等状态识别；初期排除这些复杂交易对象。

**验收：**同一批样例可复算；价格/昨收/涨跌幅在合理舍入范围内一致；未来时间、过期数据、停牌/午休均正确降级；创业板永远不能通过可买校验；缓存可离线读取且不被误标为实时。

**阶段限制：**没有分钟线时只能输出日线研究与次日确认计划，不能声称发现了盘中缩量承接或再次放量。

### 阶段二：补齐短线筛选——数据核心

**交付：分钟线、板块/市场广度、事件日历及精简候选池。**

1. 获取1/5/15分钟OHLCV，明确股/手、元、时区和分钟柱是否完成。目标保留20个交易日；免费上游只有近5日就按5日设计相应模式，不能伪造20日能力。
2. 在确认成交量单位后计算成交均价；不能把手当股计算VWAP。区分全日累计数据和单根分钟量。
3. 对同一分钟或同一已完成5分钟窗口比较昨日/近5日量能；没有历史同刻快照时明确标缺，不用昨日全天替代。
4. 统一板块分类与成分版本，计算板块与个股1/3/5日相对强弱、板块内上涨比例、成交变化、核心股联动。
5. 市场广度：涨跌家数、涨跌停、炸板等。计数应明确市场范围、ST与新股口径；不将固定9.9%涨幅当作全部股票涨停标准。
6. 公告以交易所、巨潮等原始披露为依据，保存首次公开时间、更新、链接；新闻摘要只能作线索。
7. 建立未来5个交易日财报、减持/解禁、除权、停复牌等事件日历；精确到时间无法确认时标未知。
8. 周研究池8～12只，当日计划最多2只；记录升级、降级依据和有效期。不同供应商“主力资金”统计不用于单独决定买卖。

**验收：**能还原一个候选为什么入池、为什么未通过；能用已完成分钟数据重现一次回踩确认；数据时间、单位、板块口径一致；公告不可使用未来信息；数据缺失时不产生虚假触发。

### 阶段三：形成可执行计划——适配不能持续盯盘

**交付：两类计划、风险数量计算、提醒/条件单填写草案、五日退出管理。**

#### 模式A：强势股首次回踩

板块与个股此前主动走强 → 回踩预定突破/整理区域 → 成交收缩且结构未破坏 → 在用户可查看时出现再次转强，才重新核算下单条件。不是跌到某价格就自动接。

#### 模式B：日线平台初次突破后的确认

以前一日已完成K线预先确定平台；主要看次日承接，或下午可看盘时仍成立的突破。日内高点不自动等于硬压力，也不要求机械站上20日均线。突破后距离合理止损太远或潜在空间不足则放弃。

建议复查窗口为上午开盘波动后和下午接近收盘前，可由用户实际时间调整。不存在后台任务时，不宣称系统正在持续盯盘。

#### 初始风险参数

| 参数 | 初始值/规则 |
|---|---|
| 初仓金额 | 通常1,500～2,000元，不是强制最低金额 |
| 单只上限 | 2,500元，且必须通过风险、交易单位与可用资金校验 |
| 总仓位 | 初期通常1只；最多2只不同风险来源股票，合计不超过60% |
| 单笔计划风险 | 40～60元，含合理退出价差、费用、滑点 |
| 净赔率 | 有依据的扣费潜在收益/计划风险原则上至少2，不能倒推目标凑数 |
| 数量 | 从合理失效位置倒推，按交易单位向下取整；最小单位仍超风险则放弃 |
| 时间退出 | 买入后两个交易日无有效进展且模式转弱时退出 |
| 最长期限 | 实际首笔成交日为第1个交易日，第5个交易日为最迟计划退出日 |
| 暂停复盘 | 滚动5个交易日实际净亏损约150元时暂停新仓并审查；也可更早暂停 |

数量计算采用离散候选股数逐个核算，使用用户真实佣金规则，避免把最低5元折成固定百分比后算错。佣金若包含部分规费，不能重复计费。分批交易按实际计佣方式计算，不能默认拆单没有成本。

买入价上限、止损依据、目标依据、计划有效期、成交股数、最迟退出日期及信息缺失必须同时输出。价格变化后重新算净赔率，不沿用旧结果。日期按交易日历计算，不简单加5个自然日。

### 阶段四：券商提醒与条件单闭环

用户已确认能够使用条件单，但具体支持的类型与行为需逐项核验，不预设支持OCO、跟踪止盈或定时清仓。

| 用途 | 默认辅助方式 | 关键校验 |
|---|---|---|
| 买入观察 | 价格提醒，触发后人工复查最新行情、板块和上限 | 触及价格不是自动买点；避免上涨后追价、下跌时盲接 |
| 下单 | 用户人工确认，使用限定价格和股数 | 订单提交/成交/部分成交分别记录 |
| 风险退出 | 确认券商支持后，由用户设置对应条件单 | 触发价格不等于成交价；核对可卖数量、委托方式、有效期 |
| 目标退出 | 价格提醒或用户确认的止盈条件单 | 小账户优先一次退出，防止多个订单重复占用数量 |
| 时间退出 | 第2日复查、第5日截止提醒；若券商有相应条件则人工配置 | 定时卖出能力未核实，不承诺自动清仓 |

必须覆盖的执行状态：

- 买入当天通常不可卖，止损提醒可存在，但不能生成可立即卖出当天新仓的承诺。
- 以券商显示的可卖数量决定卖单数量；加仓部分有独立可卖日期，但不延长原计划第5日截止。
- 部分成交时按实际成交数量计算持仓、风险和截止日；资金被未成交订单占用时避免重复下单。
- 止盈或止损一边成交后，核查并取消另一边残留委托/条件；只有券商确认支持且实测后才依赖互斥联动。
- 跳空、跌停、停牌、断网、条件单过期或触发未成交时，进入执行异常状态；保留提醒与处理记录，不能把计划亏损写成实际损失上限。
- 节假日按交易日历；若第5日无法成交，记录执行受限并在最早可卖时处理，不伪记为已退出。
- 本方案不上传券商密码、不接外部下单API、不替用户自动设置真实条件单；实施模拟验证不产生真实交易。

**验收：**正常成交、当天不可卖、部分成交、互斥单残留、第5日、节假日、价格跳空、触发未成交等场景均有明确状态与人工处理说明。

### 阶段五：记录、模拟与持续优化

- 保存所有计划，包括未触发、取消和失效；不只记录成交赢家。
- 流水以实际交割单/用户确认成交为准；委托成功不能当作成交成功。
- 区分入金出金与投资盈亏；净值、资金使用、费用、净利润分别记录。
- 先用约20笔计划检查执行一致性，样本数量不足以证明策略有效；继续覆盖不同市场阶段。
- 回测只用当时可获取数据，纳入T+1、佣金、滑点、停牌、涨跌停、退市与公司行动；保留未参与股票和无交易日，避免幸存者及挑选偏差。
- 评价净盈亏、平均盈亏、最大回撤、最大浮亏/浮盈、持有天数和计划偏离，不以单次涨停或错过上涨评价体系。

## 6. 拟新增接口与字段契约

以下是建议能力名称，不是现有已注册工具，也不是已确定的供应商接口。实现时映射到实际源码结构。

| 能力 | 最小输入 | 最小输出 |
|---|---|---|
| 查询快照 | 证券唯一标识、需要新鲜度 | 价量额、OHLC、前收、交易阶段、时间与质量 |
| 查询日K | 证券、日期、复权口径 | 完整OHLCV、金额、因子、完成状态 |
| 查询分钟 | 证券、频率、时间窗 | 时间对齐的OHLCV、金额、完成状态 |
| 市场/板块概况 | 市场、分类体系、对齐时刻 | 广度、强弱、量能、成分及口径 |
| 公告/事件 | 证券、已公开截止时间、未来风险窗 | 原始链接、首次披露/事件时间、分类及缺项 |
| 生成/校验计划 | 账户、模式、入场上限、失效/目标证据 | 资格、股数、费用、净赔率、截止日、拒绝理由 |
| 登记成交与复盘 | 计划版本、成交/费用、确认来源 | 实际持仓、可卖时间、净盈亏、偏差与退出状态 |

所有返回统一携带：上游来源、请求/响应/来源时间、时区、数据日期、单位、复权、延迟、交易阶段、缓存状态、异常及实际重试次数。可选字段未知用null，不用空字符串/0掩盖。

质量分别统计“字段合格、严格实时、延迟、历史、收盘确认、时钟偏差、失败”。来源时间在15点之后本身不足以证明正式收盘价已确认，需结合交易日与行情阶段。

计划状态建议：草案 → 等待条件 → 待人工确认 → 已委托 → 部分/全部成交 → 可卖持仓 → 已退出；任何阶段可进入过期、取消或执行异常。只有满足数据、资格和风险校验的计划才能进入待人工确认。

## 7. 数据来源与预算方案

### 推荐：先维持低成本

- 保留现有东方财富公开HTTPS适配器，补标准化和缓存，不把公开网站接口当成稳定性保证。
- 对日K、分钟、广度和板块适配器分别实测。可使用维护良好的接口库简化调用，但同一上游的不同封装不是独立备源。
- 公告优先链接交易所/巨潮原始披露；形成事件索引时保留检索覆盖范围与更新失败。
- 关键执行价由券商/同花顺最新行情人工核对；截图是指定时刻的人工辅助，不代替稳定历史与分钟数据。
- 预算不足或分钟线不稳定时，以已完成日线的次日确认交易为主，明确降级能力。

### 付费补充只在确有缺口后决策

2026-10-21查阅的Tushare官方价表显示：普通2000积分档200元/年、实时日线200元/月、实时分钟1000元/月；权限各自独立，购买时必须重新确认价格、范围和使用许可。该报价不是本日重新询价结果。

对5,000元账户，不默认购买1000元/月实时分钟；费用相当于本金20%，不适合作为当前起步成本。普通积分可补部分盘后数据，但不能解决盘中分钟问题。

Tushare有官方MCP文档，未来可另行评估接入；必须确认账户实际权限、宿主适配与真实暴露的工具，不声称本会话已经连通。用户已有iFinD等授权账号时可先评估API；普通看盘账号不应推定附带API。

## 8. 开发工作项与验收顺序

| 顺序 | 工作项 | 完成标准 |
|---|---|---|
| 1 | 源码、版本、发布方式盘点 | 能定位和恢复原版本，区分插件包与独立服务 |
| 2 | 快照标准化与时钟/状态校验 | 正常及异常样例全部分类正确 |
| 3 | 主板资格、交易日历、费用与持仓配置 | 无权限证券不能进入买单计划 |
| 4 | 日K/公司行动与缓存 | 120～250日可用、口径明确、错误可恢复 |
| 5 | 分钟、同刻量能、板块/广度 | 可重现模式所需证据，缺项不误触发 |
| 6 | 公告事件与风险过滤 | 原始来源和公开时点可追溯，风险覆盖可报告 |
| 7 | 两种计划及条件单参数 | 每个计划有数量、上限、失效、目标、期限、取消条件 |
| 8 | 成交与复盘记录 | 资金变动与净盈亏分离，持有期限从实际成交计算 |
| 9 | 模拟验证与正式更新 | 不下真实单验证状态；依原渠道更新并实测宿主调用 |

测试聚焦真实风险：未来时间、旧缓存、单位错配、除权、板块/代码冲突、非交易日、创业板过滤、费用最低值、T+1、部分成交和第5日截止。简单文字或格式变动不堆砌测试。

首轮建议覆盖至少3个交易日不同阶段进行人工对照，包括开盘、午休/下午、收盘；这用于发现数据和流程问题，不构成长期稳定性证明。

若上游限流，使用有限重试、并发上限、缓存与退避，不通过不断换代理或高频访问绕过限制。若实现定时采集或提醒，单独确认运行环境、时间与通知偏好；本次只写方案，不创建定时任务。
